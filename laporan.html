Pendahuluan

CodeIgniter 4 adalah framework PHP berpola MVC (Model-View-Controller) yang ringan dan cepat. Request masuk lewat public/index.php lalu dicocokkan oleh Router. Sebelum masuk ke Controller, request melewati Filter (misalnya CSRF dan cek login). Controller mengambil data lewat Model dan mengirimkannya ke View. Laporan ini membahas pembuatan dua aplikasi:

  • SIAKAD: tiga role (admin, dosen, mahasiswa). Admin mengelola mahasiswa, dosen, dan matakuliah. Mahasiswa mengisi KRS dan melihat KHS beserta IP/IPK. Dosen menginput nilai.
  • Toko Online: katalog produk dengan kategori, keranjang belanja, checkout, riwayat pesanan, serta panel admin untuk produk, kategori, dan pesanan.

Lingkungan pengembangan: Windows 11 + WSL, XAMPP (PHP 8.2 dan MariaDB), Composer, dan browser Microsoft Edge.

4Model dan CRUD

Setiap tabel punya Model dengan $allowedFields (melindungi dari mass assignment), $validationRules, dan timestamp otomatis. Password di-hash otomatis lewat callback beforeInsert dan beforeUpdate:

class UserModel extends Model
{
    protected $table         = 'users';
    protected $allowedFields = ['username', 'password', 'nama', 'role'];
    protected $beforeInsert  = ['hashPassword'];
    protected $beforeUpdate  = ['hashPassword'];

    protected function hashPassword(array $data): array
    {
        if (! empty($data['data']['password'])) {
            $data['data']['password'] = password_hash($data['data']['password'], PASSWORD_DEFAULT);
        } else {
            unset($data['data']['password']);
        }
        return $data;
    }

    public function attempt(string $username, string $password): ?array
    {
        $user = $this->where('username', $username)->first();
        return ($user && password_verify($password, $user['password'])) ? $user : null;
    }
}

Saat admin menambah dosen atau mahasiswa, akun login di users dan profilnya dibuat dalam satu transaksi database (trait HasUserAccount). Username dan password awal sama dengan NIDN/NRP. Halaman daftar dilengkapi pencarian dan paginasi (paginate(10)). Matakuliah yang sudah ada di KRS tidak bisa dihapus karena FK RESTRICT, dan admin mendapat pesan error yang jelas.

6Hak Akses User dengan Filter

Login menyimpan logged_in, role, dan data user ke session, setelah ID session diganti (session()->regenerate()) untuk mencegah session fixation. AuthFilter menerima argumen role dari route, misalnya auth:admin:

class AuthFilter implements FilterInterface
{
    public function before(RequestInterface $request, $arguments = null)
    {
        $session = session();

        if (! $session->get('logged_in')) {
            return redirect()->to('/login')->with('error', 'Silakan login terlebih dahulu.');
        }

        if (! empty($arguments) && ! in_array($session->get('role'), $arguments, true)) {
            return redirect()->to('/dashboard')->with('error', 'Anda tidak memiliki akses ke halaman tersebut.');
        }
    }
}
// app/Config/Filters.php
public array $aliases = [

4Keranjang Belanja (Session)

Keranjang disimpan di session dalam bentuk [produk_id => qty] melalui library App\Libraries\Cart, sehingga pengunjung bisa berbelanja sebelum login. Jumlah selalu dibatasi stok yang tersedia.

public function add(int $id, int $qty): ?string
{
    $produk = model(ProdukModel::class)->find($id);
    if (! $produk) {
        return 'Produk tidak ditemukan.';
    }
    if ($produk['stok'] < 1) {
        return 'Stok produk habis.';
    }

    $cart      = $this->raw();
    $baru      = ($cart[$id] ?? 0) + max(1, $qty);
    $cart[$id] = min($baru, (int) $produk['stok']);
    session()->set(self::KEY, $cart);

    return $baru > $produk['stok'] ? 'Jumlah dibatasi sesuai stok tersedia (' . $produk['stok'] . ').' : null;
}

5Checkout dalam Satu Transaksi

Stok bisa berubah antara saat produk dimasukkan ke keranjang dan saat checkout, misalnya karena pelanggan lain membeli produk yang sama. Karena itu OrderModel::buat() mengunci baris produk dengan SELECT ... FOR UPDATE, memeriksa stok, menguranginya, lalu menyimpan order dan item dalam satu transaksi. Bila satu item gagal, semua perubahan di-rollback.

$db->transBegin();
try {
    foreach ($items as $item) {
        $p = $db->query('SELECT id, nama, harga, stok FROM produk WHERE id = ? FOR UPDATE', [$item['id']])->getRowArray();
        if ($p['stok'] < $item['qty']) {
            throw new RuntimeException("Stok \"{$p['nama']}\" tidak mencukupi (tersisa {$p['stok']}).");
        }
        $total  += $p['harga'] * $item['qty'];
        $baris[] = ['produk_id' => $p['id'], 'qty' => $item['qty'], 'harga' => $p['harga']];
        $db->query('UPDATE produk SET stok = stok - ? WHERE id = ?', [$item['qty'], $p['id']]);
    }
    $orderId = $this->insert(['user_id' => $userId, 'total' => $total, 'alamat' => $alamat, 'status' => 'pending'], true);
    foreach ($baris as $b) {
        model(OrderItemModel::class)->insert($b + ['order_id' => $orderId]);
    }
    $db->transCommit();
} catch (\Throwable $e) {
    $db->transRollback();
    throw $e;
}

Controller Checkout::proses() memvalidasi alamat, memanggil buat(), mengosongkan keranjang, lalu mengarahkan ke detail pesanan dengan pesan "Pesanan berhasil dibuat."

7Panel Admin: CRUD Kategori dan Produk dengan Upload Gambar

Dashboard admin menampilkan jumlah produk, pesanan, pelanggan, dan total pendapatan (pesanan berstatus dibayar, dikirim, atau selesai). CRUD produk menerima gambar JPG/PNG/WEBP maksimal 2 MB yang disimpan ke public/uploads/produk dengan nama acak. Gambar lama dihapus saat diganti. Penghapusan yang melanggar FK RESTRICT ditangkap dan ditampilkan sebagai pesan.

private const GAMBAR_RULE = 'is_image[gambar]|mime_in[gambar,image/jpeg,image/png,image/webp]|max_size[gambar,2048]';

public function delete(int $id)
{
    $row = $this->findOr404($id);
    try {
        $this->model->delete($id);
    } catch (DatabaseException) {
        // FK order_items -> produk bersifat RESTRICT
        return redirect()->to('/admin/produk')->with('error', 'Produk tidak dapat dihapus karena sudah pernah dipesan.');
    }
    $this->hapusFile($row['gambar']);
    return redirect()->to('/admin/produk')->with('success', 'Produk dihapus.');
}

8Pengelolaan Status Pesanan

Kesimpulan

  • CodeIgniter 4 memisahkan tanggung jawab dengan jelas: Router memetakan URL, Filter menangani login, role, dan CSRF, Controller mengatur alur, Model menyimpan aturan data, dan View hanya menampilkan.
  • Hak akses cukup ditulis sekali di AuthFilter dan dipasang per route group, sehingga tidak ada pengecekan role yang tersebar di controller.
  • Migration, seeder, dan foreign key (CASCADE, SET NULL, RESTRICT) membuat database mudah dibuat ulang sekaligus menjaga integritas data, misalnya matakuliah yang sudah diambil tidak bisa dihapus.
  • Fitur bawaan seperti validasi, UploadedFile, paginasi, flashdata, dan query builder membuat CRUD dan upload file cepat dibuat sekaligus aman.
  • Kedua aplikasi (SIAKAD dan Toko Online) sudah diuji untuk setiap role, termasuk kasus gagal: login salah, akses ditolak, KRS duplikat, pembatalan KRS milik orang lain, stok tidak mencukupi, dan penghapusan data yang masih dipakai.
  • Untuk data yang diperebutkan seperti stok, transaksi database dengan SELECT ... FOR UPDATE menjamin stok tidak pernah minus dan pesanan tersimpan utuh atau tidak sama sekali.
